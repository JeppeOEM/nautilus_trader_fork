<objective>
Complete the ADDITION branch of the config-reload diff (the one seam not unit-testable in isolation): wire a reference to the live Bybit data client into `RecorderStrategy` at `recorder.py` build time, extract the on_start subscribe block into a shared `_subscribe_instrument` helper, then implement the two-phase runtime instrument load (Pattern 3 / D-09 fallback) on top of it — because `Actor.request_instrument()` is non-functional for Bybit (VERIFIED, Pitfall 1). On hot-add: `provider.load(id)` schedules the async fetch; once `provider.find(id)`/`cache` confirms the instrument (D-10), `cache.add_instrument` + `_cache_instruments` populate the caches, then the shared subscribe helper runs. Unknown ids → D-07/D-11 failure tracking. Gate the whole runtime-load path behind a `checkpoint:human-verify` live mainnet smoke (06-VALIDATION.md manual-only row).

This plan delivers the verified fallback without touching `nautilus_trader/` core. The riskiest seam (the two-phase load) is isolated into its own behavior task, on top of a pure mechanical refactor that is independently verifiable against the existing on_start tests.
Output: data-client injection wiring, the on_start subscribe-block refactor into a reusable helper, the ADD branch with two-phase load + failure tracking + count warning, mocked unit tests for addition/failure/reset, and a live smoke checkpoint.
