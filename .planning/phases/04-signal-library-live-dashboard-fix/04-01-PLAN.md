<objective>
Fix the dashboard so live 1s updates actually reach the browser. The root cause is already diagnosed: `_ingest_batch()` runs synchronously on the asyncio event-loop thread, recreating three `MultiLevelOBI` instances per instrument per second and running `statistics.stdev` over growing lists — with 100+ instruments this blocks the loop long enough that SSE `resp.write` cannot run, so frames batch or drop. A secondary bug has `_slow_loop_task` (60s Parquet recompute) overwrite the 1s-fresh OFI/OBI/microprice values in the shared `_LIVE` dict.

Four coordinated edits, all inside `dashboard.py` (plus its existing test file):
1. Make OBI persistent (`_OBI_INDS`) exactly like `_OFI_INDS` already is — DASH-06.
2. Split the single `_LIVE` cache into `_LIVE_FAST` (written by `_ingest_batch`) and `_LIVE_SLOW` (written by `_slow_loop_task`), merged at every display read with fast winning — DASH-07.
3. Offload `_ingest_batch` off the event loop via `asyncio.to_thread` so SSE writes run concurrently — DASH-05.
4. Count and log SSE `QueueFull` drops with a rate counter — DASH-08.

Purpose: Restore the every-1s live experience that Phase 2/3 built but which the blocking ingest defeats.
Output: Updated `troll/ml_signals/dashboard.py` and updated `troll/ml_signals/tests/test_dashboard_ingest.py`.
</objective>
