<objective>
Give the operator per-stream liveness visibility: log periodic heartbeats and warn when any subscribed stream goes quiet beyond its expected, per-data-type threshold (REL-03).

This plan adds a per-stream last-seen timestamp dict updated in every `on_*` handler, a second native `Clock.set_timer` named `"heartbeat"`, and a `_heartbeat` callback that logs an INFO heartbeat and a WARNING for any stale stream. Heartbeat interval and per-type stale thresholds are added to `recorder.toml` and validated positive at load time. The WS connection can stay fully up while a single symbol goes quiet — only the strategy (which sees every `on_*` event) has per-stream visibility, so this is the correct tier (Architectural Responsibility Map).

Purpose: Unattended operation needs an early signal that a specific stream died even though the socket is healthy. An external watchdog cannot see per-stream staleness.
Output: `_last_seen` + `_heartbeat` + `_stale_threshold_s` in `strategy.py`; per-handler last-seen one-liners (funding pre-dedup); new validated config fields threaded through `config.py` → `recorder.py` → `recorder.toml`; deterministic `TestClock` unit tests for registration, tracking, and stale/fresh threshold behavior.
</objective>
