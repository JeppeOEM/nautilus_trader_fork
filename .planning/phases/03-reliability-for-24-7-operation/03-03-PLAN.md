This plan closes both gaps with localized robustness fixes — no new architecture:

- CR-01 (BLOCKER, REL-02): `_run_conversion()` in strategy.py has an unguarded
  `ParquetDataCatalog(...)` construction and an unguarded `self._funding_writer.flush()`
  call OUTSIDE the per-type try/except. If either raises during a SIGTERM-triggered
  `on_stop()`, the exception propagates out of `on_stop()`, `Strategy._stop()`
  re-raises it, and the component faults during the exact shutdown sequence this
  phase exists to make reliable. Fix: wrap both in try/except using the same
  swallow-and-log pattern already used by the per-type conversion loop below them.

- WR-01 (WARNING): `restart_gap_threshold_seconds` (config.py) lacks the fail-fast
  `> 0` validation that its siblings `heartbeat_interval_seconds`/`stale_threshold_*`
  enforce at load time. A `0`/negative value silently passes through and inverts the
  intended restart-gap-warning behavior. Fix: add the same `<= 0` raise ValueError check.

After fixing, reconcile REQUIREMENTS.md: REL-02 → Complete (CR-01 closed) and
REL-04 → Complete (03-VERIFICATION.md confirms Truths 4 and 5 already VERIFIED;
the unchecked box is a documentation-sync gap, not a code gap).

Purpose: bring `_run_conversion()` and `restart_gap_threshold_seconds` validation up
to the robustness standard already established elsewhere in this same phase, so the
recorder cannot fault its own graceful-shutdown path under SIGTERM.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → recorder (`_run_conversion`) | feather files and the on-disk catalog are read/flushed during shutdown; transient I/O errors are untrusted inputs that must not fault the component |
| recorder.toml → config loader | operator-supplied `restart_gap_threshold_seconds` value crosses into runtime behavior; an out-of-range value is untrusted and must be rejected at load |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Denial of Service | `_run_conversion()` on SIGTERM (strategy.py) | mitigate | Wrap `ParquetDataCatalog(...)` and `_funding_writer.flush()` in try/except; a transient filesystem/I/O failure is logged and swallowed instead of faulting `on_stop()` and aborting the orderly Restart=always shutdown (CR-01 / Truth 7) |
| T-3-05 | Denial of Service (DoS-of-logs) | `restart_gap_threshold_seconds` validation (config.py) | mitigate | Fail-fast `<= 0` ValueError at load: a `0`/negative value would fire the restart-gap WARNING on every restart (log spam) — reject it at load, mirroring the existing heartbeat/stale-threshold checks (WR-01) |
| T-3-06 | Tampering | swallow-and-log breadth in `_run_conversion()` | accept | The catch is scoped to `Exception` around two specific statements (catalog open, funding flush); it does not mask programming errors elsewhere and matches the per-type swallow already accepted for this function. No silent data corruption: convert is idempotent and finalized-only |
| T-3-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — only edits to existing recorder source and tests; no dependency surface added |
</threat_model>
