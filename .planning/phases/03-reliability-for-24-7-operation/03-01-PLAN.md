<objective>
Make the recorder survive an unattended SIGTERM stop without losing recent data, surface restart-induced gaps in the logs, and lock in that reconnect is fully adapter-owned.

This plan refactors the existing periodic conversion body (which already calls `_convert_finalized_feather_files`, Approach B / commit `69219cca51`) into a shared `_run_conversion()` method and adds an `on_stop()` override that runs a final flush + convert while the kernel `"*"` StreamingFeatherWriter's feather files are still on disk (REL-02). Because each process restart timestamps brand-new feather filenames (finalizing the previous process's files, D-02), `on_stop()`'s convert generally catches only mid-session rotations — the previous session's tail becomes convertible on THIS process's first conversion cycle. This one-cycle parquet-visibility delay is accepted (D-03: no data loss, just delayed visibility). To make restarts observable, this plan also adds an `on_start` gap-log check (D-06): if the gap since the last recorded `ts_init` per identifier exceeds a threshold, log a WARNING so operators can alert on restart-induced gaps via journald. It also locks in REL-04 (adapter-driven reconnect) with a structural "no reconnect code" assertion and a manual forced-disconnect / stop-then-start proof.

Purpose: A `Restart=always` systemd loop drives SIGTERM on every stop/restart; the recorder must flush/convert already-finalized feather files before exit, pick up the rest on its next start, and log a visible gap warning when a restart caused a data gap. Reconnect must NOT be hand-rolled (REL-04) — the Bybit Rust WS client already handles exp-backoff reconnect + `resubscribe_all()`.
Output: `on_stop()` + `_run_conversion()` + `on_start` gap-log check in `strategy.py`; unit tests for the on_stop convert path and the gap-log check; an explicit restart-shaped (two-writer) conversion regression test; a manual integration checkpoint proving forced-disconnect resume and same-day stop-then-start no-loss.
</objective>
