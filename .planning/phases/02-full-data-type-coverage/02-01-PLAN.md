<objective>
Widen the recorder from trades-only to record five additional auto-written data types — quote ticks (REC-02), order-book deltas at configured depth (REC-03), venue-native bars per configured interval (REC-04), and mark + index prices for linear instruments (REC-06) — all flowing through the proven Phase 1 `StreamingConfig`/`StreamingFeatherWriter` -> `ParquetDataCatalog` pipeline. Add fail-fast order-book depth validation (D-03, extended to the discrete venue set per Open Question 2) before any subscription is issued.

Purpose: Deliver the bulk of Phase 2's data-type coverage as one vertical slice — after this plan a real Bybit run records five new feeds end-to-end into the catalog, and each new type reads back as its native object. Funding rate (the one type needing dedup) is intentionally deferred to Plan 02.

Output: Extended `config.py` (widened `include_types`, linear-id exposure), extended `strategy.py` (new subscriptions, depth validation, per-type conversion loop), and Wave 0 test scaffolding (fixtures + round-trip + subscription tests) for all five types.
</objective>

<phase_goal>
**As a** quant researcher running the Bybit collector, **I want to** record quotes, order-book deltas, bars, and mark/index prices for my configured instruments alongside trades, **so that** my catalog holds the full breadth of market data for backtesting — not just trade ticks.
</phase_goal>
