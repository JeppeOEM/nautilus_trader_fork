<objective>
Record funding-rate updates for linear instruments (REC-05) with value-change dedup (D-01) — a handful of rows per instrument per day instead of the ~100ms ticker flood. Resolve the one genuinely novel architectural question of the phase (how the deduped row persists and reads back, Open Question 1) with a concrete empirical spike BEFORE committing the dedup implementation, then wire `recorder.py` and prove the whole six-feed pipeline live.

Purpose: Close the last data-type gap (funding) and the last open question. This is the only feed where the framework's auto-writer cannot be used as-is (it would flood the catalog), so the strategy owns the change-gate. The empirical spike mirrors Phase 1's A2/A3 discipline so the persistence path is verified, not assumed.

Output: Extended `strategy.py` (funding subscription, `_last_funding_rate` dedup state, `on_funding_rate` gate, deduped persistence + read-back wired into the conversion loop), extended `recorder.py` (new config fields wired), funding tests (dedup behavior + native round-trip), and an approved live smoke covering all six types.
</objective>
