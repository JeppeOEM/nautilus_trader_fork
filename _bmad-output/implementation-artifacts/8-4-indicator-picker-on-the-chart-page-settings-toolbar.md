## Story

As a user of the chart page,
I want to toggle technical indicators on/off from `/chart/{id}`'s own settings toolbar and see them appear on the chart immediately,
so that I can inspect a coin with the same indicator toolkit a professional charting site offers, without editing config or reloading the page.

## Acceptance Criteria

1. **Indicator picker, catalog-driven.** `/chart/{id}`'s toolbar (`_render_chart_page`'s `widget` HTML) gains a multi-select indicator picker (a searchable dropdown-with-checkboxes — a flat list of 34 toggle chips is unusable) populated entirely from `GET /data/indicators/catalog`'s response, never a hardcoded name list in JS. Every catalog entry is selectable; selecting one renders its registered params (from the catalog's `params` dict, e.g. SMA's `period`) as inline editable fields defaulting to the catalog's own default values.
2. **Overlay indicators render on `live-chart`.** An active indicator whose catalog `panel == "overlay"` is fetched via `GET /data/coin/{id}/indicators?...&spec=...` for the currently-loaded chart window and added as additional trace(s) directly on `live-chart` (candlestick trace) — one trace per output attribute (e.g. Bollinger Bands adds `upper`/`middle`/`lower`). An overlay indicator trace is refetched/extended whenever `_loadOlderChunk` loads more candle history — never left stale/truncated relative to the candlestick trace.
3. **Oscillator indicators render in a new dedicated panel.** An active indicator whose catalog `panel == "oscillator"` appears in a new Plotly chart div (`ind-panel`), own y-scale, positioned directly below `live-chart` and above `_render_chart_page`'s existing static 7-row microstructure subplot figure — every active oscillator shares this one panel (stacked traces, one per output attribute per indicator), not one panel per indicator. This is a new panel this story introduces, not a reuse of `/coin/{id}`'s `sig-chart` (a different page, out of scope after Story 8.1).
4. **X-axis stays synced between `live-chart` and the oscillator panel.** Dragging/zooming either panel applies the resulting x-axis range to the other via a small shared helper (e.g. `_syncChartXRange(sourceDivId, rng)`, guarded against re-triggering its own `plotly_relayout` listener) — `live-chart` is the "mother" panel the oscillator panel follows.
5. **Active indicators refetch on every window/mode change, never show stale data.** Changing chart mode (Lines/Candles/Ticks), bar-size (`onBarChange`), or hitting Live/Load refetches every active indicator for the new window (mirrors the existing `_chartState=null` + refetch pattern `onBarChange`/`resetCoinLive` already use). Since every indicator is computed from OHLC candles, indicators are disabled (not silently blank) while in Ticks or Lines mode, with a one-line note why — Candles mode is the only mode where indicators can render.
6. **No regressions.** `cd troll && python -m pytest ml_signals/tests/test_dashboard_chart.py -q` passes, with a new test asserting the indicator-fetch JS helper builds the correct `spec=` query string for a given active-indicator selection (JS verified via the same extract-real-source + Node-harness method `test_dashboard_chart_pan_js.py` already uses, since no browser is available in this environment) — flag for manual in-browser confirmation before considering this story fully verified end-to-end, same caveat Stories 7.1/8.1 documented.
