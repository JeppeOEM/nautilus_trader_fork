## What Went Well

1. **Every story ran a real regression suite before `done`, continuing Epic 1's established practice.** All four stories rebuilt the Docker image (`make build-insecure`) and ran the full `ml_signals/tests dydx_collector/tests` suite before closing, every time — never skipped even when the host had no working Python environment.
2. **Real architectural forks were flagged and explicitly decided, not silently guessed.** Story 2.1's raw-`.ipynb`-vs-jupytext-format decision and Story 2.3's native-bar-aggregation-vs-custom-candle-type decision were both surfaced, reasoned through against real precedent, and recorded — not quietly picked.
3. **Root-causing over workarounds, when it mattered.** Story 2.3 didn't just note that `node.get_engines()[0]`'s post-run reporting was unreliable — it found `BacktestNode.run()`'s own `list[BacktestResult]` return value and switched to it, fixing the actual defect. Story 2.4 built on that discipline by reading `BacktestNode`/`BacktestRunConfig` source directly before choosing an attribution strategy, rather than assuming list order was safe.
4. **Dead code was deleted, not patched around.** Story 2.3 confirmed `resample.py`/`test_resample.py` had zero non-test importers and deleted both outright, continuing Epic 1's same instinct (1.1's stale test, 1.7's dead suppression flag).
5. **Deferred items were consistently logged to `deferred-work.md`, never silently dropped** — every story added specific, well-evidenced entries (the `backtest_ofi.py` sibling bugs deferred in 2.3, the skipped-symbols-in-return-value design question deferred in 2.4).
6. **Epic 1's retro action item #2 (dual-path integration-test convention) was applied on its very first real opportunity.** Story 2.2's entire Task 2 is exactly that pattern — a real consistency test proving `OrderFlowImbalance` behaves identically across its direct-replay and `BacktestEngine`-strategy consuming paths. The retro process demonstrably changed behavior, not just produced a document.

## Where We Struggled — Recurring Patterns, Not One-Off Mistakes

1. **A confirmed, unresolved native crash in the test infrastructure itself, re-scoped wider across three separate discoveries.** First found in Story 2.2 as "two `BacktestEngine`-constructing test files crash if the new one collects before `test_ofi_strategy.py`." Story 2.3 found it also occurs *within a single file* once a custom registered `Data` type is involved (worse than the original scope) — and then found it a *third* time with only built-in Nautilus types and zero custom types at all, ruling out the "custom Data type" theory entirely. This is the epic's single biggest unresolved item: never root-caused, only mitigated via a filename-collection-order + one-construction-per-file convention that Story 2.2's own review flagged as fragile (a host-venv invocation's `pytest` `addopts` could silently break the ordering and reintroduce the crash).
2. **Established Nautilus patterns had real, hidden footguns that only surfaced when actually exercised, not from reading the API.** `BacktestNode.run()`'s post-hoc engine introspection unreliably reporting empty state (2.3) and `BacktestRunConfig.raise_exception` defaulting to `False` — silently dropping a failed config's result rather than raising (2.4) — were both discovered only through hands-on verification against a real catalog, not from the type signatures alone. Both were `backtest_ofi.py`'s existing, untouched, and still-affected precedent pattern too, in the first case — meaning a bug already sat in production-facing code for a while before this epic's scrutiny found it.
3. **A design decision's own justification wasn't always tested until adversarial review pushed on it.** Story 2.4's whole reason for id-based result attribution over positional zip was to survive `BacktestNode` silently dropping a config's result — but the first-cut test suite only covered the happy path, where a naive zip would have produced identical output. The Blind Hunter reviewer caught this, not the original dev pass. This echoes Epic 1's retro finding #4 ("tests mocking too high up the stack, masking a real bug underneath") — a design decision's rationale needs its own test, not just a docstring explaining it.
4. **Docstrings occasionally overclaimed what a test actually proved.** Story 2.2's cross-context "equivalence" claim glossed over a real crossed-book-handling asymmetry between the two paths being compared; Story 2.4's "neither coin's result is a mixed/aggregated blend" claim was proven only for data throughput (`iterations`), not portfolio/account state. Both were caught in review and corrected, but the pattern recurred across two different stories.

## Epic 3 Preview — Live Paper-Trading Integration Proof

Goal: a Dummy Strategy consumes every signal validated in Epic 2 and runs live against real dYdX market data in paper mode, closing the full research→backtest→live loop — genuinely net-new: the first sanctioned `TradingNode`/`Strategy` usage anywhere in `troll/`, structurally isolated per the amended AD-8, with real-money execution unreachable by any default or accidental config state.

**Real dependency on Epic 2:** Story 3.2's Dummy Strategy must consume `Microprice`, `OrderFlowImbalance`, `MultiLevelOBI`, `MultiLevelOFI`, `OnlineLogisticTrend` via the exact same shared implementation Epic 2 validated in research/backtest (FR10) — no reimplementation for the live context. Epic 2's Task 1 audits across Stories 2.1/2.2 already confirmed all five are correctly import-ready for this.

**A materially different risk profile than Epic 2.** Every Epic 2 story was backtest/notebook-only — no live network connection, no real capital at risk, failure modes were incorrect research conclusions at worst. Epic 3 introduces a live `TradingNode` connecting to real dYdX market data and a paper-trading execution path with an explicit, deliberate carve-out for eventually enabling real-money execution. This is the first epic where FORK-01/AD-8's "no `TradingNode`/`DataEngine` in `troll/`" rule is being *amended*, not just followed — a bigger architectural step than anything in Epic 2.

**Directly relevant open item:** the epic's unresolved `BacktestEngine`/`BacktestNode` native-crash finding (see above) is specific to *backtest* construction — untested whether the same or a related fragility could affect `TradingNode` construction in Epic 3's live context. Worth a quick sanity check early in Story 3.1 rather than discovering it mid-epic.

**No architectural surprises from Epic 2 requiring an Epic 3 re-plan.** The plan holds as written.
