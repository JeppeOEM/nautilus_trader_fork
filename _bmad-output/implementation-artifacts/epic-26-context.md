# Epic 26 Context: The gate as an aggregate

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Finish the DDD migration by moving capture last. The collector's single fail-closed write gate becomes one pure domain service (`SecondSampler`) over explicit aggregates (`LiveBook`, `TradeIntake`, `FeedGroup`). Venue differences come in as pure policy values rather than `Collector` subclass hook overrides, so no venue can override the gate and every counter has a name. The work runs in three steps. First the domain shape is built in place, behind the hot-path budget (26.1, done). Then it moves into `platform/capture/` with `capture/venues/<v>/` packages and new entrypoints (26.2, done). Last, a closeout deletes every remaining shim and rewrites both architecture spines so they describe the code that actually runs (26.3, remaining). A small archive-only story (26.1b, done) rides in the same queue to make the off-site backup an explicit, visible setting.

## Stories

- Story 26.1: `LiveBook`, `TradeIntake`, `FeedGroup` and a pure `SecondSampler`, in place
- Story 26.1b: The off-site catalog backup is an explicit setting, off until a storage target exists
- Story 26.2: `capture/` package and `capture/venues/<v>/` with new entrypoints
- Story 26.3: Closeout: last shims gone, spines reconciled, guardrails permanent

## Requirements & Constraints

- **Hot-path budget.** The ingest path is measured against the recorded baseline (`platform/tests/fixtures/hotpath_baseline.json`) with stdlib `tracemalloc`/`perf_counter_ns` only, never pytest-benchmark. Allocations per message must not exceed the baseline, and wall time per message must stay within 2x. Results go in `docs/DATA_INTEGRITY_AUDIT.md`. `on_data` stays an O(1) enqueue. There is no per-delta or per-trade wrapper, event or verdict object; domain events exist only per sampled second and per state transition.
- **Deployable alone, published language frozen.** Every story ships on its own. Parquet schemas and catalog directory names, every Redis payload (`snapshots:raw`, `collector:status`, `collector:control`, ...), SQLite and TOML store schemas, compose service names, env vars and the `platform/data/` bind mounts stay unchanged. `DydxSecondSnapshot` and `OpenInterest` are persistence identifiers and keep their names.
- **Shims.** A moved module's old path keeps a pure re-export shim: `from <new> import <names>`, a `DeprecationWarning` and `REMOVE_AFTER = "<story key>"`, nothing else defined. `test_namespace.py` enforces `old.X is new.X` and exactly one Arrow registration per kernel class, and fails once the named story is `done`.
- **Same-commit doc and packaging updates.** Every move updates, in the same commit: `platform/CLAUDE.md` citations, `ARCHITECTURE.md`, `docs/DATA_DICTIONARY.md`, the three dockerfiles' `COPY` sets, compose `command:` lines, and both Makefile test lists (`test`, `test-live-paper`).
- **Parent-spine Deferred items.** A story that resolves one strikes it in the parent spine with an amendment. Already struck: the dYdX OI-poll liveness item, the empty-top skip (26.1), the `data_api` image gap, the reader-side crossed-book skip and the OI-vs-`volume24h` namespace item. The writer-to-reader imports item is marked resolved but not struck. The raw-frame harness (`capture_hl_ws.py`) item stays open until a fourth venue needs it. Buffer durability, gate-version skew, rejection-rate observability, ranking retention, `bots:history` TTL and the Beta pin stay deferred.
- **Data integrity.** Fail closed: a rejected sample is dropped, logged and ledgered, and no validity flag is ever added. The empty-top rejection has a rate-limited WARNING and ledger site `collector.empty_top`. Nothing is silently dropped or muted, and root cause comes before mitigation. The DATA-04/DATA-08 policy tests (dYdX uncross ladder, Bybit `u` canary including the zero-level message, Hyperliquid full snapshot) and the 22.12/22.13/22.14 tests must pass unchanged.
- **Deferred operator actions.** VPS steps never park a story. They go into `docs/DEPLOY_CHECKLIST.md`'s "Deferred operator actions" as one entry headed with the story key and commit, and the story finalizes `done` through normal review. 26.2's redeploy (all three collectors via `make redeploy-all`, Dozzle check, `GET /api/errors` flat) is recorded there.
- **Backup setting (26.1b, shipped).** The archive `config.toml` has a required `backup_enabled`, committed `false`. When it is off, no `backup_catalog` step runs, one WARNING is logged at start and `archive:status` shows `"backup": "disabled"`. When it is on, a missing `RCLONE_REMOTE`/`RCLONE_BUCKET` refuses start. Audit D-33 stays open as an explicit choice.

## Technical Decisions

- **Hexagonal layering inside the context.** `domain/` imports only the stdlib, `kernel/` and `nautilus_trader.model`/`nautilus_trader.core`, with no I/O, asyncio, Redis, SQLite or Parquet. `application/` holds the `Protocol` ports, the service and the asyncio loops. `infrastructure/` adapters are imported only by composition roots. `capture` depends only on `kernel` and `observability` (plus `collection_control.domain`, imported only by `capture/infrastructure/config.py`); candles enter only through the injected `SecondSink` port. There is no `platform.` import prefix, no DI container and no event bus.
- **Aggregates.** `LiveBook` wraps the Nautilus `OrderBook` by reference and is the only module naming the concrete book class. It holds staleness, crossed-since, resync-pending, level tags, last `u`, and venue-time pending deltas bounded by `hold_back + _VENUE_AHEAD_NS` (on overflow it drops, ledgers `collector.pending_deltas` and resyncs). `TradeIntake` owns the bounded id window, the stale-history filter, per-feed arbitration (`duplicate` for a same-feed replay, `duplicate_feed` for a copy via another feed or REST) and the late/ahead counters, all reported at flush. `FeedGroup` owns per-feed liveness, reconnect detection, one-sided outage comparison and `BackfillRequest` scheduling; `trades_only` feeds and REST rows never stamp WS liveness.
- **`SecondSampler`** is pure and returns accepted snapshots, `SampleRejected`s and requested actions. Under venue time it closes second `S` at `S + 1 + hold_back_seconds`. `FlushBatch` carries the newest trade group (and that instrument's later rows) while younger than 5 s; `SecondSink.apply` gets the flushed batch.
- **Policies** are pure and synchronous (no logging, ledgering or `await`), and `test_boundaries.py` treats them as domain: `CrossedBookPolicy.step(...) -> Uncrossed | StillCrossed | ResyncRequested`, `LevelTagger`, `SequenceCanary`, `BookTimeSource`, `BackfillCapability`. The core defaults live in `capture/domain/policies.py`. dYdX has the uncross ladder and level tagger, and Bybit has the `u` canary. Hyperliquid has no `policies.py` because the core defaults fit a full-snapshot venue.
- **`CaptureService` (the renamed `Collector`).** It is never subclassed, and `test_boundaries.py` fails if a subclass appears. It takes a required `venue`, its client as a factory `(OnData, Ledger) -> VenueFeed`, and the composition root's extra loops through `add_loops`. The per-venue open-interest loops became the generic `CaptureService.poll_loop`. It executes `ResyncRequested` and drops the local book *before* awaiting `VenueFeed.resync_orderbook`, a deliberate reading of the rule. It is the only ledger caller in capture, and its sites are listed in `capture/application/sites.py`.
- **Ports and adapters.** `ports.py` declares `VenueFeed`, `VenueTradeHistory`, `ArchiveWriter`, `LiveStream`, `Notifier`, `SecondSink` and `OnData`. `ArchiveWriter` (`parquet_writer.py`) owns the Parquet write, quarantine, instrument definitions and the batch encoder, and is the only module naming the encoder. `LiveStream` (`redis_stream.py`) owns the Redis publish. Backfill admission (`admit_backfill`) is application code, and the fetch is the port.
- **As-built tree (26.2).**
  - `capture/domain/`: aggregates, verdicts, events, policies, `flush_batch`, `trade_history`.
  - `capture/application/`: `capture_service`, `ports`, `sites`, `config` (`CoreConfig`), `trade_backfill`, `book_check`, `feed`.
  - `capture/infrastructure/`: `parquet_writer`, `redis_stream`, `capture_lock`, `gap_markers`, and `config`, the one venue-config loader.
  - `capture/venues/<v>/`: `client.py` (the `VenueFeed` ACL), `trade_history.py`, `policies.py` (dYdX, Bybit), `open_interest.py` (dYdX, Bybit), `book_snapshot.py` (Bybit REST cross-check, Hyperliquid), `config.py` (config class, caps, `CONFIG_PATH`), `__main__.py` (the composition root with `build_capture`/`build_capture_from_file`) and `tests/`.
  - Compose runs `python3 -m capture.venues.<v>`. The compose service `collector` kept its name; renaming it for symmetry was rejected.
- **Guardrails.** `test_boundaries.py` walks AST imports against the context graph; its legacy map is what 26.3 deletes. `test_images.py` checks each image's `COPY` set against its entrypoint's import closure. `test_hotpath.py` and `test_namespace.py` run in `make test`. The spine's Reviewer Gate is `lint_spine.py` plus the version lens.
- **Spine reconciliation (26.3).** Each `[TARGET]` in the DDD spine is re-verified against the code. It is either rewritten `[ADOPTED]` with `path:line` citations, or kept with a reason and a Deferred entry. The capability map's "today" citations (for example `collector_core/...`, `dydx_collector/...`, `live_paper/...`) are replaced by `capture/...` target paths, and `troll/...` citations in both spines are re-pointed to `platform/...`. The spine's 26.1/26.2 amendments already record the as-built deviations, so they are the reference for what the code is.

## Cross-Story Dependencies

- The order 26.1 → 26.2 → 26.3 is fixed; 26.1b (archive only) is independent. Only 26.3 remains.
- 26.3 removes every shim from Stories 23.1–26.2, including `collector_core`, `dydx_collector`, `bybit_collector` and `hyperliquid_collector` (keyed `REMOVE_AFTER = "26-3-..."`).
