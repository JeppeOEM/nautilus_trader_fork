# Story 15.1: Facade scaffold, SPA static serving, and Docs page

Status: done

## Story

As the dashboard operator,
I want a working end-to-end pipeline (React SPA built and served by `data_api`, with generated API types) proven by the simplest existing page,
so that every later Epic 15 story lands on a working foundation instead of untested plumbing.

## Acceptance Criteria

1. **`troll/frontend/` is scaffolded via Vite + React + TypeScript (strict mode)** at the architecture spine's pinned versions (React 19.3.0, Vite 8.3.0 + `@vitejs/plugin-react` 6.1.1), with route-based code-splitting configured (each page a separate lazy-loaded chunk, per spine Consistency Conventions) even though only one real page (`DocsPage`) exists yet — the splitting mechanism must be in place, not retrofitted in a later story.
2. **`data_api/app.py` serves the built SPA via FastAPI's native `app.frontend()` helper (AD-F1a)**, never a hand-rolled `StaticFiles` mount + catch-all route. An unmatched `/api/*` path returns a JSON 404, never SPA HTML (Consistency Conventions) — proven by a test.
3. **`data_api` declares a Pydantic response model for one new pilot route, `GET /api/health`**, and the frontend's TypeScript types for it are generated from `data_api`'s OpenAPI schema at build time (AD-F5) into `frontend/src/api/`, never hand-written to match. This route is genuinely useful going forward (a real liveness check), not throwaway scaffolding — it is not removed once its pilot job is done.
4. **`/docs` (Docs page, FR45) is rebuilt as a React page** reading `dashboard.py`'s existing `docs_page.py` content (`HEAD`/`BODY`/nav/indicator-detail/KB-detail data and the hand-rolled `svgArchitecture()` diagram) — every section present on today's `/docs` page has a corresponding section on the new page (a diffable content checklist, not a rewrite of the text), served through the new pipeline end-to-end.
5. **`troll/data_api.dockerfile` exists as its own file**, layered on `nautilus-trader-base:1.229.0`, with an added Node build stage that runs `vite build` against `troll/frontend/` and copies `dist/` into the final image — `node_modules`/build tooling never appear in the runtime layer. `troll/collector.dockerfile` is unchanged (still builds `collector`/`dashboard`/`ranking_engine`/`bot_tui`).
6. **`docker-compose.yml`'s `data_api` service builds from `troll/data_api.dockerfile`** instead of `troll/collector.dockerfile`, still `network_mode: host`, still binding `127.0.0.1` only (SEC-01 unchanged). The `dashboard` service is **not** touched or removed in this story (removal is Story 15.10's cutover, once every page has a working React equivalent per NFR9) — `dashboard.py` keeps running exactly as today, including its existing `DATA_API_URL` remote-mode calls to `data_api`'s current unprefixed routes (`/metrics/*`, `/catalog/*`), which this story must not rename or move.
7. **A smoke test proves the pipeline end-to-end**: a Vitest render test for `DocsPage`, plus a pytest hitting `GET /docs` (the new SPA route, served by `app.frontend()`) and asserting a 200 with the expected HTML shell, plus a pytest for `GET /api/health` asserting the Pydantic-modeled JSON response.
