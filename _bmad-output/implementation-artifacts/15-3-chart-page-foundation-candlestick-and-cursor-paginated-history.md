# Story 15.3: Chart page foundation — candlestick + cursor-paginated history

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As the dashboard operator,
I want a coin's candlestick chart to load its recent window immediately and fetch older bars progressively as I scroll back,
so that I never wait on a multi-megabyte full-history fetch just to see a chart.

## Acceptance Criteria

1. **`GET /api/candles/{instrument_id}` accepts `before_ns` (cursor) + `limit` (server-clamped max) and returns `{"items": [...], "has_more": bool}`, at most `limit` rows strictly older than `before_ns`** (spine AD-F3). `data_api/routes/candles.py` is a new file — it reuses `ml_signals.candles.candle_dicts_from_snapshots` and `ml_signals.catalog_stats.query_second_snapshots` unchanged (no new aggregation logic, AD-F2); the route's wire contract deliberately replaces today's `/catalog/candles/{iid}`'s `start_ns`/`end_ns` shape rather than preserving it, per AD-F1's "upgrade during relocation" clause. **The existing `/catalog/candles/{iid}` route in `data_api/app.py` is untouched** — `dashboard.py`'s remote-mode caller (`_fetch_json` → `DATA_API_URL/catalog/candles/...`) still depends on it verbatim until Story 15.10's cutover deletes `dashboard.py`; do not rename, move, or remove it.
2. **The chart page's first load fetches only the most recent window** — `frontend/src/hooks/useCandles.ts`'s initial call uses `limit=120` (matching today's `_CANDLE_VISIBLE_BARS` default, `dashboard.py:206`), never the full catalog range (FR40).
3. **Scrolling back triggers the next page via the same `before_ns`/`limit` contract**, wired through `lightweight-charts`' `chart.timeScale().subscribeVisibleLogicalRangeChange()` — when the visible range's left edge approaches the earliest currently-loaded bar (mirror today's margin-based refill trigger, `dashboard.py:206`'s `_CANDLE_REFILL_MARGIN_BARS`), the hook fetches one more page and prepends it. The operator never observes a request whose response exceeds one page.
4. **`has_more: false` stops further requests for that direction** — reaching the true start of a coin's history never retries or hangs; a short page (`items.length < limit`) with `has_more: true` is legal (e.g. a thin-trading window) and must not be treated as exhaustion.
5. **A genuine gap in the queried range gets an explicit gap marker, never a silently-omitted row.** Today's `candle_dicts_from_snapshots`/`aggregate_ohlc` (`ml_signals/candles.py`) silently produce no entry for a bar interval with zero underlying snapshots — correct for `dashboard.py`'s continuous polling, but insufficient here: a `lightweight-charts` candlestick series interpolates a flat connecting line across any missing time point unless it receives an explicit whitespace data point (`{time}`, no OHLC) at the gap. `routes/candles.py` must detect a spacing between consecutive aggregated candles greater than one `bar_seconds` interval and insert a `null`-valued item (`{"t": ..., "o": null, "h": null, "l": null, "c": null, "v": null}`) at the gap boundary — mirroring `dashboard.py:1485`'s `_price_series_rows` null-insertion pattern, adapted from per-snapshot to per-bar granularity. The frontend renders it as a visible break (`lightweight-charts` native whitespace-data support), never interpolated or flat (AD-F6).
6. **Exactly one `lightweight-charts` `createChart()` instance is created on the chart page in this story**, in `frontend/src/components/chart/LightweightChart.tsx` (or equivalent) — the single-instance invariant (AD-F4) starts here even though indicator panes arrive in Story 15.4, so nothing created in this story is later discarded/recreated by that story.
7. **A boundary test proves a large `before_ns`/`limit` request never returns more than `limit` rows** — `routes/candles.py` enforces a server-side max on `limit` (a module constant, e.g. `_MAX_CANDLES_LIMIT`) regardless of what the client requests; this extends MEM-01 (never load an unbounded catalog slice) to the new API surface, closing the exact class of bug this session's `/catalog/candles` split from `/catalog/snapshots` already fixed once for the old route (`ml_signals/candles.py:110-115`'s docstring: a 4-hour window of full order-book depth serialized to ~12MB and took 30-60s over the SSH tunnel).
8. **`pytest troll/data_api/tests` covers `/api/candles` against real `DydxSecondSnapshot` objects and a real (not mocked) `ParquetDataCatalog` fixture** (TEST-01/03) — following `troll/ml_signals/tests/test_chart_data.py`'s and `troll/data_api/tests/test_data_api.py`'s existing pattern (`tempfile` + real catalog + real domain objects, no mocking of Nautilus internals).

## Tasks / Subtasks

- [ ] Task 1 — `data_api/routes/candles.py`: cursor-paginated candles route (AC: #1, #5, #7)
  - [ ] Define `CandleItem` (`t: int`, `o/h/l/c/v: float | None` — `None` on all four OHLC fields marks a gap point, per AC #5) and `CandlesResponse(items: list[CandleItem], has_more: bool)` as Pydantic models (AD-F5 — the frontend's TS type is generated from these, never hand-written).
  - [ ] `GET /api/candles/{instrument_id}?before_ns=<int>&limit=<int>&bar_seconds=<int, default 60>`: declare its own module-level `CATALOG_PATH: str = os.environ.get("CATALOG_PATH", ...)` constant, **do not import `data_api.app`'s `CATALOG_PATH`** (importing `app` from `routes/candles.py` would be circular, since `app.py` imports `routes.candles`) — same pattern `redis_bus.py` already established for its own `REDIS_URL` constant (Story 15.2 precedent). Clamp the requested `limit` to a server-enforced `_MAX_CANDLES_LIMIT` module constant (AC #7) before doing anything else.
  - [ ] Query a time window bounded by `limit`/`bar_seconds` ending at `before_ns` (e.g. `start_ns = before_ns - limit * bar_seconds * 1_000_000_000 * <safety multiplier, e.g. 2>`) via `query_second_snapshots(CATALOG_PATH, instrument_id, start_ns, before_ns)`, then `candle_dicts_from_snapshots(snapshots, bar_seconds)` — this bounds the read by construction (MEM-01/AD-F3), never an unbounded `start_ns=0` scan. Keep only candles with `t < before_ns`, take the most recent `limit` of them.
  - [ ] **`has_more` is genuinely tricky — a short page must not be misread as exhaustion (spine AD-F3 explicit warning).** The catalog API (`ParquetDataCatalog.query()`) has no cheap "does earlier data exist" primitive — implementation-owned approach: after building the page, issue one more *equally-bounded* probe query for the window immediately preceding the page's earliest kept candle (same width as the main query); `has_more = True` if that probe returns any snapshot at all, `False` otherwise. This keeps every read bounded (never an open-ended `start_ns=0` scan) at the cost of a possible false `has_more: false` on an extremely sparse/illiquid instrument with a real gap wider than one probe window — an explicitly acceptable, YAGNI-consistent tradeoff for a single-operator tool (document this tradeoff in Completion Notes; revisit only if it's ever observed to be wrong in practice).
  - [ ] Insert an explicit gap-marker item (AC #5) wherever two consecutive kept candles' `t` values differ by more than `bar_seconds * 1000` ms.
  - [ ] Register the router in `app.py` **above** the existing `GET /api/{full_path:path}` catch-all (same required ordering as Story 15.2's `rankings`/`live` routers — a route registered after it silently 404s, confirmed failure mode from Story 15.1).

See the official `lightweight-charts` "Infinite history" tutorial pattern (`timeScale().barsInLogicalRange()` to measure how much unseen data remains) — [https://tradingview.github.io/lightweight-charts/tutorials/demos/infinite-history](https://tradingview.github.io/lightweight-charts/tutorials/demos/infinite-history).

## Dev Notes

- **This is the base every later Epic 15 chart story builds on** (per `epic-15-context.md`'s Cross-Story Dependencies): Story 15.4 adds indicator panes via `chart.addPane()` onto the one `createChart()` instance this story creates; Story 15.5 (live edge) depends on this story's candle-aggregation path; Story 15.7 (Lines mode) reuses this exact cursor-pagination contract on a new `/api/snapshots` route. Getting the single-instance invariant (AC #6) and the pagination contract shape (AC #1) right here is load-bearing for 4 more stories — do not under-scope this one as "just wire up a chart."
- **Old vs. new namespace coexist, same as Story 15.1/15.2 established:** `/catalog/candles/{iid}` (old, `start_ns`/`end_ns`, `dashboard.py`-only) and `/api/candles/{instrument_id}` (new, `before_ns`/`limit`, frontend-only) are two different routes on the same `data_api` instance, serving two different callers. This is intentional — do not merge them or redirect one to the other. `/catalog/candles` is deleted only in Story 15.10, alongside `dashboard.py`.
- **The gap-marker requirement (AC #5) is new behavior, not a straight relocation of `ml_signals.candles`.** `candle_dicts_from_snapshots`/`aggregate_ohlc` today silently produce zero output for an empty bucket — fine for `dashboard.py`'s continuous live polling (a missing bar just isn't drawn yet, and shows up once trades resume), but wrong for a candlestick series receiving a fixed historical page: `lightweight-charts` will draw a connecting line across the missing time unless it gets an explicit whitespace data point. Do the gap-detection in `routes/candles.py` (post-aggregation, comparing consecutive `t` values), not inside `ml_signals/candles.py` itself — that module's existing behavior is still correct for its other caller (`dashboard.py`'s `/catalog/candles`), so don't change its shared function's contract.
- **`has_more` has no ready-made catalog primitive to answer it correctly and cheaply** — `ParquetDataCatalog.query()` (`nautilus_trader/persistence/catalog/parquet.py:1578`) takes `start`/`end`/`identifiers`/`where` but has no "does anything exist before X" or count-only mode for a custom PyO3 type like `DydxSecondSnapshot`. The one-more-bounded-probe-query approach in Task 1 is a genuine implementation-owned design call (same category as the architecture spine's own "codegen tool TBD"/"exact font TBD" deferrals) — a reasonable default, not the only possible answer. Whatever approach is chosen, it must stay bounded (no `start_ns=0` unbounded scan) per AD-F3/MEM-01, and it must not treat "fewer than `limit` items returned" alone as proof of exhaustion (the spine explicitly calls this out as a modeling trap).
- **`lightweight-charts` 5.2.1's multi-pane/whitespace-data API is already `[VERIFIED lightweight-charts 5.2.1, 2026-09-13]`** in the architecture spine (2 days before this session) — no re-verification needed. The official "Infinite history" tutorial (linked in Task 3) is the canonical pattern for `subscribeVisibleLogicalRangeChange` + `barsInLogicalRange`-driven scroll-back loading; this story's `useCandles` hook should follow it rather than reinventing the refill-margin logic from scratch, even though the *bar-count constants* (120/20) come from `dashboard.py`'s existing JS, not the tutorial.
- **Testing `lightweight-charts` under Vitest/jsdom is a known pitfall**: `jsdom` provides a `<canvas>` element but no real 2D rendering context, and `lightweight-charts` needs one to actually draw. Mock the library at the module boundary for component/hook tests (assert `createChart`/`addCandlestickSeries`/`setData` were *called* with the right arguments) rather than trying to render a real chart in the test environment or adding the `canvas` npm package (troll/CLAUDE.md-adjacent user preference: minimize dependencies, hand-roll over adding a library unless necessary/high-value/well-maintained — a headless-canvas dependency for this one assertion is not that).
- **No Dockerfile changes needed this story** — `troll/data_api.dockerfile:28-30` already `COPY`s `troll/ml_signals` and `troll/data_api` wholesale (new files under `routes/` are picked up automatically, same as Story 15.2's `redis_bus.py`/`routes/rankings.py`/`ws/live.py` needed none either).
- **`troll/CLAUDE.md` constraints that apply:** FORK-01/FORK-02 (nothing under `nautilus_trader/`/`crates/` touched), MEM-01 (extended to the new API surface per AD-F3, see AC #7/Task 1), NAUT-02 (`ParquetDataCatalog`/`query_second_snapshots`/`candle_dicts_from_snapshots` reused unchanged, no new hand-rolled aggregation), DATA-01 (gap honesty — AC #5's whole point), DESIGN-01 (no indicator panes, no Lines mode, no live edge in this story — those are 15.4/15.7/15.5's jobs).
