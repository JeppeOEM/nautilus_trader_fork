## What Went Well

1. **Every story ran a real regression suite before `done`** — never just isolated unit tests. When the host had no working Python env, the fallback was Docker (`make build-insecure && make test`), not skipping verification. Story 1.4 is the clearest example: after the code review found the `+`/space encoding bug, the image was rebuilt and the full suite re-run to prove the fix and confirm zero regressions.
2. **Patterns compounded instead of being reinvented.** `_is_fresh`/`_watchlist_ids` (1.3) became the basis for `_current_ranks()` (1.4). `housekeeping_logger` (1.6) became `critical_logger` (1.7). The lean stdlib-only fetch-helper shape (`watchlist.py`) was mirrored exactly by `rank_history.py`.
3. **Dead/stale code was deleted, not patched around.** 1.1 found and fixed a stale test asserting pre-fix behavior. 1.7's dead suppression flag was removed, not reworked.
4. **Deferred items were consistently logged to `deferred-work.md`**, not silently dropped or scope-crept into whatever story was open.

## Where We Struggled — Recurring Patterns, Not One-Off Mistakes

1. **State not cleaned up on lifecycle transitions — the single most common bug class in the epic (4 instances across 3 stories).** 1.1's hot-reload not refreshing delta-store state; 1.5's `_last_sequence` not resetting on resubscribe *and* resync tasks never cancelled on shutdown; 1.6's `_raw_ring` never cleaned up on unsubscribe. There is no standing convention or checklist item for "does this state get reset/removed on every lifecycle transition (subscribe/unsubscribe/resubscribe/shutdown)?"
2. **Unguarded empty-input crashes on a rarely-exercised branch (2 instances, same root cause).** 1.5 and 1.6 both had an `IndexError` reachable only via the same Rust-side asymmetry — `OrderbookUpdate` missing the `is_empty()` guard that `OrderbookBatch` has.
3. **Ordering-of-state-write bugs (3 instances).** 1.1's prune cadence, 1.5's sequence-tracker-written-before-apply (could mask corruption), 1.7's flag-cleared-before-it-could-take-effect. Same shape each time: state written before the operation it's meant to guard actually completes.
4. **Tests mocking too high up the stack, masking a real bug underneath (1.4, but systemically relevant).** The `+`/space encoding bug shipped because tests mocked `urlopen` at the client boundary instead of round-tripping through aiohttp's real query parser.

**Complexity signal:** 1.4 and 1.5 carried the most real bugs (8 and 5) — both touched cross-cutting state (SQLite migration + timezone/encoding edge cases; the Rust/Python boundary + an async state machine). 1.6/1.7 were lighter (2 and 1) because they built on 1.5's now-hardened state. 1.3's review was the noisiest (12 dismissed findings), reading as reviewer over-triggering on a comparatively simple story rather than genuine complexity.

## Action Items (Process Improvements)

1. **Add a lifecycle-cleanup checklist item** — any new subscribe/unsubscribe/resubscribe/shutdown transition must explicitly state what tracking state gets reset or removed. Owner: Amelia (apply during future story dev-story work). No deadline — applies from the next story onward.
2. **Add an integration-test convention for dual-path handlers** — any function reachable via two live code paths (e.g. a background loop *and* an HTTP handler) needs at least one test that drives the real integration surface (e.g. a real `aiohttp` `TestServer`/`TestClient`), not just the pure function underneath. Owner: Murat / applied during code-review triage. No deadline — applies from the next story onward.
