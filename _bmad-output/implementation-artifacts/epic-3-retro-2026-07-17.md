## What Went Well

1. **The AD-8 amendment held exactly as designed, with zero scope creep in either direction.** Story 3.1 scaffolded `TradingNode`/`Strategy` usage cleanly separated from `dydx_collector`/`ml_signals`, and Story 3.2 extended it by importing only `ml_signals.indicators`' pure classes — never its stateful internals, never `ml_signals.watchlist`'s I/O-performing `fetch_watchlist`. The AD-4 boundary discipline established in Epic 1/2 transferred cleanly to a genuinely new module.
2. **The two-signals-must-agree design for real-money gating (Story 3.1) survived its own adversarial review intact.** Neither Blind Hunter nor Edge Case Hunter found a path to reach real money by accident — the design held up under real scrutiny, not just self-review.
3. **Adversarial review caught a real tooling bug, not just code bugs.** Building Story 3.2's review diff, a `git diff HEAD -- <mixed tracked+untracked pathspec>` command silently produced an empty diff for the tracked files. The Blind Hunter reviewer correctly flagged the diff as suspiciously incomplete relative to its own stated scope — the diff-construction bug was caught and fixed before it could hide real changes from review, a genuine win for having an adversarial layer at all.
4. **Verification-before-dismissal was applied consistently, not just claimed.** Several review findings were dismissed only after reading the actual Nautilus source directly: `Actor._stop()`'s automatic `cancel_timers()` (ruling out a "missing on_stop cleanup" finding), and the dual `subscribe_quote_ticks`/`subscribe_order_book_deltas` subscription being genuinely necessary, not redundant (confirmed via `nautilus_trader/adapters/dydx/data.py`'s `_active_delta_subs` gating). Neither was accepted on the reviewer's say-so or dismissed on the dev's say-so — both were checked.
5. **Real design decisions were made and disclosed, not silently assumed.** The EXTERNAL-vs-INTERNAL bar aggregation choice (no live credentials available to verify empirically) and the live equivalent of `MultiLevelOBI`/`MultiLevelOFI`'s backtest-calibrated 1s sampling cadence (no `DydxSecondSnapshot` exists live) were both genuinely open design questions with no obvious answer from reading the backtest code alone — both were reasoned through explicitly and documented, not guessed.

## Where We Struggled — Recurring Patterns, Not One-Off Mistakes

1. **A task was marked complete without fully implementing its own stated scope.** Story 3.2's Task 2 explicitly said to add "thresholds" to `PaperConfig`/`RealMoneyConfig`, but only `instrument_id`/`trade_size` were added — the Completion Notes described this partial scope as if it were the whole task. Caught only by an independent Acceptance Auditor pass reading the actual diff against the actual task text, not by the implementing pass itself. This is the same shape as Epic 2's "docstrings occasionally overclaimed what a test actually proved" pattern — a self-report not matching the artifact, just showing up as an implementation gap this time instead of a test-coverage gap.
2. **Epic 2's action item #2 (Murat) recurred: a design decision's own failure mode still isn't test-covered.** Story 3.2's `orders_inflight()` guard exists specifically to survive "a signal stays true across ticks while an order is still in flight" — but no test actually forces that race condition; `BacktestEngine` fills market orders close to synchronously, making the failure mode hard to construct without mocking (which `TEST-03` bars). The guard is verified correct by reading `nautilus_trader/examples/strategies/orderbook_imbalance.py`'s identical precedent, not by a test exercising the specific failure. Flagged honestly rather than silently claimed as tested — but this is the second epic in a row this exact pattern has shown up.
3. **A config field existed for a value the code's own docstring said must never change.** `book_snapshot_interval_secs`'s docstring said "must stay at 1.0," but it was still a free-form, unvalidated config field until review caught it. Fixed by deleting the field entirely (a constant, per `troll/CLAUDE.md`'s DESIGN-01) rather than adding validation — a cleaner resolution than Epic 2's typical "add a guard" pattern, worth noting as a good instinct to repeat.
